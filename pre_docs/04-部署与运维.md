# 部署与运维 Spec

## 1. 硬件与系统要求

| 项 | 要求 |
|---|---|
| GPU | **2× NVIDIA RTX 4090 48GB**（每 worker 一卡；单卡 4090 49GB 亦可跑单 worker） |
| 显存 | 每卡 ≥ 45 GB（DiT 32GB INT8 + TE 26GB 分时加载 + VAE 5GB） |
| 磁盘 | ≥ 200 GB（模型 63GB + venv 6GB + wheels 0.75GB + 输出增长） |
| OS | Ubuntu 22.04（当前内核 5.15.0-113） |
| Python | 3.10（venv） |
| CUDA | 随 torch wheel；`--fast autotune cublas_ops` 需 cuDNN benchmark 可用 |

## 2. 目录布局（部署假定）

```
/home/ubuntu/comfy/            # 本仓库
├── ComfyUI/                   # 上游引擎 clone（自有 .git）
├── venv/                      # 共享虚拟环境
├── wheels/                    # 离线 wheel（网络受限时装依赖）
├── logs/                      # 运行日志
├── api_server.py
├── ecosystem.config.cjs       # PM2 清单（生产）
└── start_services.sh          # tmux 方案（调试）
```

模型放 `ComfyUI/models/` 对应子目录（清单见 `03-ComfyUI工作流.md` §5）。

## 3. 依赖安装

```bash
# 在线
python3 -m venv venv && source venv/bin/activate
pip install -r ComfyUI/requirements.txt
pip install fastapi uvicorn aiohttp pydantic   # api_server 侧

# 离线（本机已有 wheels/）
pip install --no-index --find-links=wheels/ -r ComfyUI/requirements.txt
```

## 4. 启动方式（二选一）

### 4.1 PM2（生产推荐，当前在用）

```bash
pm2 start ecosystem.config.cjs
pm2 save && pm2 startup     # 开机自启
```

进程清单：

| name | script | 关键参数 |
|---|---|---|
| `comfy-gpu0` | `ComfyUI/main.py` | `--listen 0.0.0.0 --port 8188 --cuda-device 0 --fast autotune cublas_ops` |
| `comfy-gpu1` | `ComfyUI/main.py` | 同上 + `--port 8189 --cuda-device 1 --output-directory .../output/gpu1 --user-directory .../user/gpu1` |
| `minimax-h3-api` | `api_server.py` | env `COMFY_HOSTS=127.0.0.1:8188,127.0.0.1:8189` |

所有进程 `env.LD_LIBRARY_PATH=""`（清除沙箱注入，防 CUDA 初始化失败）。
`.env`（若存在）由 `ecosystem.config.cjs` 顶部逻辑注入所有进程。

> **单卡过渡期**：`comfy-gpu1` 会因找不到 cuda-device 1 crash-loop。临时 `pm2 stop comfy-gpu1 && pm2 save`；插上第二张卡后 `pm2 start comfy-gpu1`，API 无需重启。

### 4.2 tmux（调试）

```bash
./start_services.sh start    # 会话 comfy-multi：window0=gpu0, 1=gpu1, 2=api
./start_services.sh attach   # 进入观察
./start_services.sh stop|status
```

日志 tee 到 `logs/comfy_gpu{0,1}.log`、`logs/api.log`。

## 5. 端口与防火墙

| 端口 | 进程 | 暴露建议 |
|---|---|---|
| 8000 | api_server | 公网（唯一入口） |
| 8188 / 8189 | ComfyUI workers | **仅内网/本机**，不应公网直达 |
| 22 | ssh | 公网（建议加固） |

同机邻居（勿动）：clipforge、openrouter-relay（各自 PM2 cluster 模式）。

## 6. 健康检查与监控

```bash
# 服务整体
curl -s http://127.0.0.1:8000/health | jq

# 单 worker 直查
curl -s http://127.0.0.1:8188/system_stats | jq '.devices[].name'
curl -s http://127.0.0.1:8188/queue | jq '{running: .queue_running|length, pending: .queue_pending|length}'

# PM2
pm2 list; pm2 logs minimax-h3-api --lines 50

# GPU
nvidia-smi; watch -n2 nvidia-smi
```

任务级监控：`python3 monitor.py <task_id>`（轮询 API + 从 ComfyUI history 提取精确执行起止时间戳）。

## 7. 日志

| 来源 | 位置 |
|---|---|
| PM2 模式 | `~/.pm2/logs/{name}-out.log / -error.log` |
| tmux 模式 | `logs/comfy_gpu0.log`、`logs/comfy_gpu1.log`、`logs/api.log` |
| ComfyUI 崩溃 dump | `ComfyUI/core.*`（已 gitignore，可 `rm` 回收磁盘） |

## 8. 常见故障排查

| 症状 | 排查 |
|---|---|
| `/health` degraded | 对应 worker 端口未监听 → `pm2 logs comfy-gpuN` 看启动错误 |
| 提交 502 | worker `/prompt` 拒绝：多为 graph 节点校验错（node_errors）或模型文件缺失 |
| 任务恒 queued | worker 挂或队列堆积 → 查 `/queue`；确认 GPU 显存 `nvidia-smi` |
| CUDA Error 304 | `--cuda-device N` 的卡不存在（单卡期跑 gpu1 的典型错） |
| CUDA init failed | 进程环境残留 `LD_LIBRARY_PATH` → 确认 PM2 env 已置空 |
| 视频代理 404 | `_video_worker` miss 且各 worker `/view` 均无此文件：检查 worker1 是否写到 `output/gpu1/` 且带 `subfolder=video` |
| API 重启后旧任务查不到 | 预期行为：`_worker_assign` 内存态丢失，fallback worker0（见 `01-架构设计.md` §2.3） |

## 9. 输出管理与清理

```bash
# 输出目录（按 worker 分离）
ComfyUI/output/video/*.mp4          # gpu0
ComfyUI/output/gpu1/video/*.mp4     # gpu1

# 磁盘回收
find ComfyUI/output -name '*.mp4' -mtime +7 -delete
rm -f ComfyUI/core.*                # 崩溃 dump
```

> 输出未做生命周期管理，长期运行需 cron 清理或对象存储外移。

## 10. 升级路径

| 场景 | 操作 |
|---|---|
| 更新上游 ComfyUI | `git -C ComfyUI pull && pm2 restart comfy-gpu0 comfy-gpu1` |
| 更新 api_server | `pm2 restart minimax-h3-api`（重启丢失在途任务映射，见已知限制） |
| 换模型权重 | 覆盖 `models/` 对应文件 + 改 `api_server.py` 顶部常量 + 重启 worker |
| 加第 3 张卡 | `COMFY_HOSTS` 追加 `127.0.0.1:8190`，PM2 加 worker 段，重启 api |
