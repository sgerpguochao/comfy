### 7.3 `--voiceover on` 不带 `--voiceover-text`


✅ 正确拦截，来源 `generate_h3.py:148-149`。

### 7.4 `--bgm on` 不带 `--bgm-file`

```bash
$ python generate_h3.py --mode t2v --prompt "test" --duration 5 --bgm on
--bgm on 需要 --bgm-file 指定 BGM 音频文件
exit=1
```

✅ 正确拦截，来源 `generate_h3.py:150-151`。

### 7.5 `--size` 格式错误（**发现输入校验缺陷**）

```bash
$ python generate_h3.py --mode t2v --prompt "test" --duration 5 --size 1344-768
# 没有报错，提交了任务，最终生成了视频
exit=0
```

⚠️ **缺陷**：`--size 1344-768`（错误格式）被静默忽略，脚本继续以默认 1344×768 提交任务。

**根因**（`generate_h3.py:155-161`）：

```python
width, height = args.width, args.height
if not width and not height and args.size and "x" in args.size:
    w, h = args.size.split("x", 1)
    ...
```

代码只在 `size` 中**包含** `x` 时才解析。`1344-768` 不含 `x` 时直接跳过，没有报错。

**建议修复**（参考方案）：

```python
if args.size and not (args.width and args.height):
    if "x" not in args.size:
        raise SystemExit(f"--size 格式应为 宽x高，例如 1344x768，收到: {args.size}")
    w, h = args.size.split("x", 1)
    try:
        width, height = int(w), int(h)
    except ValueError:
        raise SystemExit(f"--size 格式错误: {args.size}")
```

**影响**：低严重。任务仍能完成（分辨率走默认），但用户错误使用 `--size` 时无感知。建议在文档或下一版脚本中修复。


| 维度 | 数据 |
|------|------|
| 总用例 | 6 个功能 + 6 个校验 = 12 |

| 最快任务 | 165.7s（Case 4 i2v 静音） |
| 最慢任务 | 226s（Case 1、2、6 文生视频） |

### 耗时分布

| 任务类型 | 平均耗时 | 原因 |
|----------|---------|------|
| 文生视频（t2v） | ~226s | 无图片编码节省 |
| 图生视频（i2v 单帧） | ~166s | 首帧已编码进 latent，省一次完整 denoise 步骤？实际可能与分配到哪个 GPU 有关 |
| 图生视频（i2v 首末帧） | ~181s | 比单帧略慢（多一张图 conditioning） |
| 文图生视频（t2i2v） | ~169s | 同 i2v |

> 实测图生视频比文生视频**快约 60 秒**。这与"`i2v` 模型用 fl2va 而 `t2v` 用 t2va"路径有关，fl2va 可能因首帧已确定 latent 起点而收敛更快。

## 10.12 测试结论

### ✅ 通过的功能

- 文生视频（t2v）基本路径
- `--sfx off` 静音剥离路径
- 文图生视频（t2i2v）+ 中文口播混流
- 图生视频（i2v）无 prompt 默认提示词
- 首末帧生成 + 静音 + BGM 组合（最复杂路径）
- 文生视频 + 原声 + BGM 三轨混流
- 所有必填参数校验（i2v/t2i2v 的 image、voiceover 的 text、bgm 的 file、last-frame 必搭 image）
- argparse 自动 choices 校验（mode）

### ⚠️ 发现的问题

1. **`--size` 格式错误被静默忽略**（`generate_h3.py:155-161`）：仅在含 `x` 时校验，应改为显式报错。
   - 严重程度：低（任务仍能完成，只是分辨率走默认）
   - 建议修复：见 10.9.7.5 节

### 建议改进

1. **日志可观测性**：脚本当前只打印"状态: queued/success"，不显示 worker 分配、frame_count 等。可加 `--verbose`。
2. **失败重试**：网络/ComfyUI 偶发失败时，脚本直接 exit。建议加有限次数自动重试。
3. **进度展示**：5 秒轮询看不到 GPU 真实执行进度，可选加 `--progress` 显示百分比。
