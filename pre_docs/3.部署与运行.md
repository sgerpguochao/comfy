# 3. 部署与运行

## 3.1 硬件 / 软件依赖

| 项 | 要求 |
|----|------|
| GPU | NVIDIA，≥2 张（双卡部署；单卡也可但需改环境变量） |
| 显存 | 每卡 ≥24 GB（INT8 模型 + 激活缓存） |
| CUDA | 12.x |
| Python | 3.10+（venv 在 `comfy/venv/`） |
| FFmpeg | ≥5.0（用于混流；`ffprobe` 需可执行） |
| Edge-TTS | `pip install edge-tts`（已包含在 venv） |
| 依赖清单 | `comfy/ComfyUI/requirements.txt`、`comfy/requirements.txt` |

## 3.2 目录结构准备

```bash
cd /home/ubuntu/minmax/comfy

# 1. 确认模型到位（每个文件 ≥ 数十 GB）
ls -lh ComfyUI/models/diffusion_models/ \
       ComfyUI/models/text_encoders/ \
       ComfyUI/models/vae/

# 2. 启动 venv（首次）

pip install -r ComfyUI/requirements.txt

# 3. 安装 edge-tts（口播必需）
pip install edge-tts
```

## 3.3 启动方式（三选一）

### 方式 A：tmux 多窗口（推荐）

```bash
./start_services.sh start    # 创建会话 comfy-multi：worker0 / worker1 / API 三个窗口
./start_services.sh status   # curl /health 看状态
./start_services.sh attach   # tmux attach 看日志
./start_services.sh stop     # kill 会话
```

底层逻辑（节选）：

```9:34:comfy/start_services.sh
COMFY_DIR=/home/ubuntu/minmax/comfy/ComfyUI
VENV=/home/ubuntu/minmax/comfy/venv/bin/python
API=/home/ubuntu/minmax/comfy/api_server.py
LOG_DIR=/home/ubuntu/minmax/comfy/logs
SESSION=comfy-multi
API_PORT=8000
W0_PORT=8188
W1_PORT=8189
OUT_DIR=/home/ubuntu/minmax/comfy/ComfyUI/output
USER_DIR=/home/ubuntu/minmax/comfy/ComfyUI/user
FAST="--fast autotune cublas_ops"
# worker 1 隔离 output/user/db，详见 2.2 节
```

### 方式 B：PM2 守护

```bash
pm2 start ecosystem.config.cjs
pm2 logs minimax-h3-api
pm2 save && pm2 startup
```

适用场景：服务器长期在线、希望开机自启、`pm2 monit` 监控。

### 方式 C：手动逐个启动（开发调试）

```bash
# GPU 0
env -u LD_LIBRARY_PATH venv/bin/python ComfyUI/main.py \
  --listen 0.0.0.0 --port 8188 --cuda-device 0 --fast autotune cublas_ops

# GPU 1
env -u LD_LIBRARY_PATH venv/bin/python ComfyUI/main.py \
  --listen 0.0.0.0 --port 8189 --cuda-device 1 \
  --output-directory ComfyUI/output/gpu1 \
  --user-directory ComfyUI/user/gpu1 \
  --database-url sqlite:////home/ubuntu/minmax/comfy/ComfyUI/user/gpu1/comfyui.db \
  --fast autotune cublas_ops

# API
env -u LD_LIBRARY_PATH COMFY_HOSTS=127.0.0.1:8188,127.0.0.1:8189 \
  venv/bin/python api_server.py
```

> **为什么 `env -u LD_LIBRARY_PATH`？** 沙箱/CI 环境会注入与 CUDA 不兼容的 `LD_LIBRARY_PATH`，导致 `cudaMalloc` 失败。显式 unset 是项目里所有 worker 都加的兜底。

## 3.4 配置项

| 项 | 默认 | 说明 |
|----|------|------|
| `COMFY_HOSTS` | `127.0.0.1:8188,127.0.0.1:8189` | ComfyUI worker 列表，逗号分隔 |
| API 端口 | `8000`（硬编码于 `api_server.py` 末尾） | 修改需改源码 |
| Worker 端口 | 8188/8189 | 改 `--port` 与 `COMFY_HOSTS` 同步 |
| 输出前缀 | `video/minimax_<task前缀>` | 与 worker output dir 配合 |

## 3.5 一键生成脚本

```bash
# 默认用 comfy/prompt.txt，竖屏 768x1344，15 秒
bash gen.sh

# 自定义：横屏 5 秒
bash gen.sh my.txt 1344 768 5
```

内部逻辑（`gen.sh`）：

```13:17:comfy/gen.sh
PY="python3"
command -v python >/dev/null 2>&1 && PY="python"
"$PY" /home/ubuntu/minmax/comfy/client_example.py \
  "$(cat "$PROMPT_FILE")" "$WIDTH" "$HEIGHT" "$DURATION"
```

等价于直接 `python client_example.py "<prompt>" 768 1344 15`。

## 3.6 健康检查

```bash
curl http://127.0.0.1:8000/health
```

预期返回（两个 worker 都可达时）：

```json
{"status": "ok", "workers": [
  {"worker": 0, "url": "http://127.0.0.1:8188", "ok": true},
  {"worker": 1, "url": "http://127.0.0.1:8189", "ok": true}
]}
```

任一 `ok=false` 即 `status="degraded"`。

## 3.7 日志

- API：`logs/api.log`
- GPU 0 worker：`logs/comfy_gpu0.log`
- GPU 1 worker：`logs/comfy_gpu1.log`

`monitor.py <task_id>` 可对单个任务拉取 ComfyUI `/history` 中的 `execution_start` / `execution_success` 时间戳，统计精确执行时长。
