# 6. 后处理（混流）机制

## 6.1 为什么需要后处理

H3 模型本身支持**原生音效**（环境音、动作音）。但典型的"短视频生产"场景下，需要叠加：

- **中文人声旁白**（edge-tts）
- **背景音乐 BGM**（本地/URL）
- **静音**（剥掉原声，只保留画面）

这些操作**ComfyUI 节点实现起来繁琐且调试困难**，因此项目把后处理放在 API 层用 **ffmpeg** 实现。

## 6.2 触发条件

提交时若设了以下任一字段，任务完成后自动执行后处理：

| 字段 | 含义 |
|------|------|
| `voiceover` 非空 | 中文口播文案，任务完成后 edge-tts 合成 → 混流 |
| `no_audio=true` | 剥掉 H3 原生音效（仅画面 + 静默） |
| `bgm` 非空 | BGM 路径/URL，混入背景音乐（可与上述组合） |

任务完成后**只对第一个视频**做一次后处理（`_vo_done` 集合防重复）。

## 6.3 组合规则

```
no_audio=True 且无口播且无 BGM  ──►  纯静音（剥掉原声）
有口播 / 有 BGM（任意组合）    ──►  混流：
                                     原声（除非 no_audio）+
                                     口播（延迟 400ms）+
                                     BGM（按音量叠加、循环、淡出）
```

> **BGM 音量淡出**：默认 2 秒或视频时长 × 20%（取小者），避免音乐突然截断。

**纯静音**分支：

**混流**分支（核心）：

```618:648:comfy/api_server.py
audio_sources, labels = [], []
if not mute:
    audio_sources.append("[0:a]aformat=sample_rates=44100:channel_layouts=stereo")
    labels.append("[a0]")
if tts_path:
    inputs += ["-i", tts_path]
    audio_sources.append("[1:a]aformat=sample_rates=44100:channel_layouts=stereo,adelay=400|400")
    labels.append("[a1]")
if bgm_path:
    inputs += ["-stream_loop", "-1", "-i", bgm_path]
    bgm_idx = 1 + (1 if tts_path else 0)
    dur = await _probe_duration(src) or 10.0
    fade = min(2.0, dur * 0.2)
    audio_sources.append(
        f"[{bgm_idx}:a]aformat=sample_rates=44100:channel_layouts=stereo,"
        f"volume={bgm_volume},atrim=0:{dur:.3f},asetpts=N/SR/TB,"
        f"afade=t=out:st={max(0.0, dur - fade):.3f}:d={fade:.3f}")
    labels.append(f"[a{bgm_idx}]")
mix_labels = "".join(labels)
filter_cmd = (f"{';'.join(s + l for s, l in zip(audio_sources, labels))};"
              f"{mix_labels}amix=inputs={len(labels)}"
              f":duration={'longest' if bgm_path else 'first'}"
              f":dropout_transition=0[aout]")
```

**关键设计**：

| 元素 | 含义 |
|------|------|
| `aformat=sample_rates=44100:channel_layouts=stereo` | 统一所有源到 44.1kHz 立体声（amix 要求） |
| `adelay=400\|400` | 口播延迟 400ms，避免首句被截断 |
| `-stream_loop -1` | BGM 不够长时无限循环 |
| `volume={bgm_volume}` | 用户调节 BGM 音量 |
| `atrim=0:{dur},afade=t=out:st=...:d=...` | 截齐到视频时长 + 末尾淡出 |
| `amix=inputs=N:duration=...:dropout_transition=0` | 多源混音 |
| `-c:v copy -c:a aac -b:a 192k` | 视频流直接复制（极快）、音频转 AAC 192k |

## 6.6 文件目录

```
muxed/
├── tts_<task_id>.mp3       # edge-tts 合成的中文旁白
├── bgm_<uuid>.mp3          # 从 URL 下载的 BGM 缓存
├── muted_<task_id>.mp4     # 纯静音产物
└── muxed_<task_id>.mp4     # 混流产物（默认对外 URL）
```

## 6.7 重启恢复

任务元数据写入 `api_state.json`，API 重启后自动恢复：

- 哪些任务待口播 → 轮询时仍能完成混流
- 哪些任务已静音 → 不会再次写入
- 哪些任务分配到哪个 worker → `_worker_assign` 决定去哪查 history

> **重要前提**：worker 必须保持运行且输出文件未删。否则 `_resolve_src` 会回退到 worker `/view` HTTP 拉取，仍能补救。

## 6.8 失败容忍

| 失败点 | 行为 |
|--------|------|
| TTS 合成失败 | 跳过口播，退化为"原声 ± BGM" |
| BGM 下载失败 | 跳过 BGM，退化为"原声 ± 口播" |
| ffmpeg 混流失败 | 写日志、返回 None；客户端拿到的是 worker 原视频（无后处理 URL 标记） |
| worker 不可达 | 任务元数据仍在，下次重启后能重试 |
