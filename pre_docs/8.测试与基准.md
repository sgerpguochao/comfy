# 8. 测试与基准

## 8.1 测试脚本一览

| 脚本 | 用途 | 入口 |
|------|------|------|
| `test_h3.py` | 单 worker 文生视频最小验证 | 直连 ComfyUI `:8188` |
| `test_two.py` | 双 worker 并行 + 自动下载 | 通过 API `:8000` |

## 8.2 单 worker 最小验证（`test_h3.py`）

绕过 API，直接构造 ComfyUI `/prompt` JSON 提交任务。**用于诊断 worker 自身是否正常**。

```bash
python test_h3.py "一只橘猫..." 832 480 4 42
# 参数: <prompt> <width> <height> <duration> <seed>
# 可选第 6 个参数指定 worker: http://127.0.0.1:8188 或 :8189
```

输出示例：

```
[submit] comfy=http://127.0.0.1:8188 task_id=abc123... node_errors=None
[poll] still queued/running...
[done] outputs: {...}
```

适用场景：

- worker 启动后第一次验证（模型加载是否成功）
- API 层出现问题时定位是 worker 问题还是 API 问题
- 调试新参数（自定义 width/height/duration）

## 8.4 并发基准（`bench.py`）

```bash
python bench.py http://127.0.0.1:8000 832 480 4 20 4 "海浪拍打礁石"
# 参数: <base> <width> <height> <duration> <steps> <N> <prompt>
```

提交 N 个任务，记录每个任务的：

- 分配的 worker
- 总耗时（提交 → 完成）
- 视频 URL

```31:39:comfy/bench.py
seed_base = int(time.time()) % 10 ** 9  # 每次运行取随机种子，避免触发 ComfyUI 执行缓存
for i in range(N):
    resp = post(f"{BASE}/api/v1/generate", {
        "prompt": f"{PROMPT} (第{i+1}段)", "width": WIDTH, "height": HEIGHT,
        "duration": DURATION, "seed": seed_base + i, "steps": STEPS})
    tasks.append({"id": resp["task_id"], "worker": resp["worker"],
                  "submit": time.time()})
```

> **为什么用时间戳 seed？** ComfyUI 有执行缓存机制（相同 prompt+seed 可能命中缓存返回历史结果），随机 seed 强制真实执行。

典型结果（双卡，832×480，4 秒，steps=20）：

```
[submit] task1 -> worker0 id=abc...
[submit] task2 -> worker1 id=def...
[done]   task1 worker0 status=success elapsed=68.2s
[done]   task2 worker1 status=success elapsed=71.5s

总耗时(全部完成): 71.5s
```

两条任务基本并行（71s vs 单条 68s），说明负载均衡正常工作。

## 8.5 单任务耗时监控（`monitor.py`）

```bash
python monitor.py <task_id> http://127.0.0.1:8000
```

每 15s 轮询一次 `/api/v1/task/<id>`，完成后从 ComfyUI `/history/<id>` 提取精确执行时间戳：

```32:48:comfy/monitor.py
msgs = h[task_id].get("status", {}).get("messages", [])
ts = {}
for m in msgs:
    if isinstance(m, list) and len(m) == 2 and isinstance(m[1], dict):
        key = m[0]
        if key.startswith("execution_start"):
            ts["start"] = m[1].get("timestamp", 0)
        elif key.startswith("execution_success"):
            ts["success"] = m[1].get("timestamp", 0)
        elif key.startswith("execution_error"):
            ts["error"] = m[1].get("timestamp", 0)
```

输出：

```
[poll]     0s status=queued
[poll]    15s status=queued
[poll]    30s status=queued
[poll]    45s status=success
[history] worker=http://127.0.0.1:8188 执行时长=12.3s (start=15:30:01, end=15:30:13)
[done] status=success api_轮询期间=45.1s
```

**`执行时长`** 是 ComfyUI 实际 GPU 推理时间；**`api_轮询期间`** 是从提交到 API 端返回 success 的总时间（含队列等待 + 后处理）。

适用场景：

- 排查"任务卡住"是真在跑还是队列堆积
- 评估后处理（口播混流）的耗时占比
- 性能回归测试基线

## 8.6 测试覆盖矩阵

| 测试 | 验证项 |
|------|--------|
| `test_h3.py` | ComfyUI worker 自身、模型加载、GPU 推理 |
| `test_two.py` | API 多 worker 调度、output 隔离、视频下载 |
| `bench.py` | 并发调度、负载均衡、缓存规避 |
| `monitor.py` | 历史时间戳、队列等待 vs 实际执行 |
| `client_example.py` | 完整链路（生成/图生/口播/静音/BGM） |

## 8.7 推荐测试流程

```bash
# 1. 启动所有服务
./start_services.sh start
./start_services.sh status  # 等到 status="ok"

# 2. 单 worker 验证模型
python test_h3.py "测试 prompt" 832 480 4 42

# 3. 双 worker 并行
python test_two.py http://127.0.0.1:8000

# 4. 完整功能验证（口播混流）
python client_example.py "..." --voiceover "测试配音"

# 5. 性能基线
python bench.py http://127.0.0.1:8000 832 480 4 10 4 "海浪拍打礁石"

# 6. 拿一个 task_id 跑监控
python monitor.py <task_id_from_step_2>
```
