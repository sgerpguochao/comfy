# 9. 运维与故障排查

## 9.1 进程管理

### tmux 模式

```bash
./start_services.sh start    # 启动
./start_services.sh status   # 健康检查
./start_services.sh attach   # 进入 tmux 会话看日志（Ctrl+B 切窗口）
./start_services.sh stop     # 停止
```

会话名 `comfy-multi`，三个窗口：

- 窗口 0：GPU 0 worker (`comfy_gpu0.log`)
- 窗口 1：GPU 1 worker (`comfy_gpu1.log`)
- 窗口 2：API 服务 (`api.log`)

### PM2 模式

```bash
pm2 start ecosystem.config.cjs
pm2 list                       # 查看所有进程
pm2 logs minimax-h3-api        # 跟踪 API 日志
pm2 logs comfy-gpu0            # 跟踪 GPU 0 worker
pm2 restart all                # 重启所有
pm2 stop all                   # 停止所有
pm2 save && pm2 startup        # 持久化 + 开机自启
```

## 9.3 常见故障

### 9.3.1 CUDA 初始化失败

**症状**：

```
RuntimeError: CUDA initialization failed
```

**排查**：

```bash
# 1. 看 LD_LIBRARY_PATH 是否被沙箱注入
env | grep LD_LIBRARY_PATH

# 2. start_services.sh / ecosystem.config.cjs 已用 env -u 清掉
#    如果手动启动，请加: env -u LD_LIBRARY_PATH
```

### 9.3.2 worker 端口冲突

**症状**：

```
OSError: [Errno 98] Address already in use
```

**排查**：

```bash
lsof -i :8188
lsof -i :8189
lsof -i :8000

# 杀掉残留进程
kill -9 <pid>
```

### 9.3.3 模型加载失败

**症状**：

```
UNETLoader: minimax_h3_fl2va_int8_convrot.safetensors not found
```

**排查**：

```bash
ls -lh /home/ubuntu/minmax/comfy/ComfyUI/models/diffusion_models/
ls -lh /home/ubuntu/minmax/comfy/ComfyUI/models/text_encoders/
ls -lh /home/ubuntu/minmax/comfy/ComfyUI/models/vae/

# 检查文件完整性（应该 ≥ 10 GB 不为 0）
# 如果 .lock 文件存在，说明上次下载中断
ls -lh /home/ubuntu/minmax/comfy/ComfyUI/models/**/*.lock 2>/dev/null
# 删掉 .lock 重试
```

### 9.3.4 任务卡在 queued 状态

**症状**：`/api/v1/task/<id>` 始终返回 `status: queued`。

**排查**：

```bash
# 1. 看 worker 是否还在
curl http://127.0.0.1:8000/health

# 2. 直接看 ComfyUI 队列
curl http://127.0.0.1:8188/queue
curl http://127.0.0.1:8189/queue

# 3. worker log 有没有 OOM
grep -i "out of memory" logs/comfy_gpu*.log
```

**常见原因**：

- 上一个任务把 worker 弄崩了（OOM、节点错误）→ 重启 worker
- _submit_lock 死锁（理论上不可能，但可重启 API）

### 9.3.5 口播混流失败

**症状**：任务成功但没有 `audio_processed: true`，或视频没声音。

**排查**：

```bash
# 1. edge-tts 是否装好
venv/bin/python -m edge_tts --help

# 2. 看 API 日志
grep "post-process" logs/api.log

# 3. 看 muxed/ 目录
ls -lh muxed/
# tts_<task_id>.mp3 是否生成？
```

**常见原因**：

- 网络问题：edge-tts 调用 Microsoft 在线 TTS，需要出网
- 音色 ID 错误：用 `--voice zh-CN-XiaoxiaoNeural` 试
- ffmpeg 版本太旧：`ffmpeg -version` 应 ≥ 5.0

### 9.3.6 两 worker 输出覆盖

**症状**：提交两个任务只看到 1 个视频。

**排查**：

```bash
# 看两个 worker 的 output 目录
ls ComfyUI/output/
ls ComfyUI/output/gpu1/

# 如果两个任务产物都在 ComfyUI/output/ 而非分开，
# 说明 worker 1 没传 --output-directory
# 修正: 重新启动 worker 1
```

正确配置（见 `start_services.sh`）：

```bash
env -u LD_LIBRARY_PATH $VENV $COMFY_DIR/main.py \
  --listen 0.0.0.0 --port $W1_PORT \
  --cuda-device 1 \
  --output-directory $OUT_DIR/gpu1 \
  --user-directory $USER_DIR/gpu1 \
  --database-url sqlite:////home/ubuntu/minmax/comfy/ComfyUI/user/gpu1/comfyui.db \
  $FAST
```

### 9.3.7 OpenAI 兼容端点 502

**症状**：`POST /videos` 返回 502，`detail` 含 ComfyUI 节点错误。

**排查**：

- 通常是 prompt 中 `@ImageN` 引用数量与 `reference_images` 数量不匹配
- 或 `resolution` 字段传了未支持的值
- 看 `logs/api.log` 找到对应 task_id，再 `python monitor.py <id>`

### 9.3.8 提交慢 / 队列堆积

**症状**：`/api/v1/generate` 返回延迟高，或 `_pick_worker` 选到 round-robin 兜底。

**排查**：

```bash
# 看两个 worker 的队列长度
for i in 0 1; do
  echo "GPU $i:"
  curl -s http://127.0.0.1:$((8188+i))/queue | python -c "import sys,json;d=json.load(sys.stdin);print(f'  running={len(d[\"queue_running\"])} pending={len(d[\"queue_pending\"])}')"
done
```

**优化**：

- 加 GPU：`COMFY_HOSTS` 加上新 worker
- 减时长：duration ≤ 5 秒最优
- 减步数：steps=10 是速度/质量折中

## 9.4 重启流程

### 完全重启（保留任务）

```bash
./start_services.sh stop
# 修改配置（如有）
./start_services.sh start
```

API 会从 `api_state.json` 恢复任务元数据，轮询时仍能完成未完成的后处理。

### 完全清理（不推荐）

```bash
./start_services.sh stop
rm -rf ComfyUI/output/*
rm -rf ComfyUI/output/gpu1/*
rm -rf muxed/*
rm api_state.json
./start_services.sh start
```

## 9.6 性能调优

### 显存优化

```bash
# 启动时加 --lowvram / --gpu-only / --reserve-vram
venv/bin/python ComfyUI/main.py --listen 0.0.0.0 --port 8188 \
  --cuda-device 0 --lowvram --fast autotune cublas_ops
```

`--lowvram`：把不活跃的 DiT block 卸载到 CPU
`--gpu-only`：禁用 CPU offload
`--reserve-vram 4`：保留 4 GB 给其他进程

### 吞吐优化

| 优化项 | 收益 | 副作用 |
|--------|------|--------|
| `--fast autotune cublas_ops` | +70% | 首跑慢 |
| `--fp8_e4m3fn-unet`（如模型支持） | 节省 50% 显存 | 轻微画质损失 |
| 并发 2-3 任务/GPU | 提升利用率 | 单任务延迟略增 |
| `steps=10` vs `steps=20` | 快 1.7× | 质量略降 |

### 日志清理

```bash
# 定期清理 ComfyUI 缓存
rm -rf ComfyUI/temp/*
rm -rf ComfyUI/output/*  # 注意：会清掉所有生成结果
```

建议保留最近 7 天的产物到归档目录。

## 9.7 监控建议

生产环境建议接入：

1. **GPU 利用率**：`nvidia-smi dmon` 或 Prometheus DCGM exporter
2. **API 响应时间**：nginx access log + GoAccess / Promtail
3. **任务成功率**：`/api/v1/task/<id>` 状态分布 → 业务侧聚合
4. **磁盘空间**：`ComfyUI/output/` 与 `muxed/` 是大头
5. **edge-tts 出网**：定时调用一次 `/api/v1/generate`（含 voiceover）做心跳

## 9.8 安全建议

API 服务**没有任何鉴权**。公网暴露前必须：

```nginx
# nginx 反向代理示例
server {
    listen 443 ssl;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    # 简单 token 鉴权
    if ($http_authorization != "Bearer YOUR_SECRET_TOKEN") {
        return 403;
    }

    # 限流
    limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
    limit_req zone=api burst=20 nodelay;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_read_timeout 600s;  # 视频生成耗时长
    }
}
```

更高级的方案：

- API Gateway（Kong / APISIX）做 token + QPS + 用户配额
- 上游业务侧做用户级 token 与计费
